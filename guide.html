PLANCRAFT PRO AI

Flutter Web Edition — Setup, Deploy & Usage Guide

Flutter 3.22 Web Riverpod GoRouter Hive 100% Offline No APK

1. How to Run Locally

1Install Flutter 3.22+ and confirm the web target is enabled:

flutter --version
flutter config --enable-web

2From the project root, fetch dependencies:

flutter pub get

3Run in Chrome for local development:

flutter run -d chrome

4Or just build a static release you can double-click / serve locally:

flutter build web --release
cd build/web
python3 -m http.server 8080
# then open http://localhost:8080
✅ No backend, no API keys, no internet required at runtime — every screen (particles, splash, 2D plans, 3D viewer) is rendered with Flutter's CustomPainter and persisted locally via Hive (IndexedDB).

2. How to Deploy to GitHub Pages

1Create a GitHub repo (e.g. plancraft-pro) and push this project to the main branch.

2Build with the correct --base-href — this MUST match your repo name exactly, with leading and trailing slashes:

flutter build web --release --base-href "/plancraft-pro/"
⚠️ If you skip --base-href, the deployed site will load a blank white page on GitHub Pages because asset paths will point to the domain root instead of /plancraft-pro/.

3Upload the contents of build/web to GitHub Pages. Two ways:

Option A — Manual (gh-pages branch)

cd build/web
git init
git add .
git commit -m "Deploy PlanCraft Pro AI"
git branch -M gh-pages
git remote add origin https://github.com/<you>/plancraft-pro.git
git push -f origin gh-pages

Then in your repo: Settings → Pages → Branch: gh-pages → / (root).

Option B — Automatic (GitHub Actions, recommended)

This project already ships a workflow at .github/workflows/deploy.yml. Just:

  1. Edit the --base-href value inside that file to match your repo name.
  2. In your repo: Settings → Pages → Source: GitHub Actions.
  3. Push to main — it builds and deploys automatically on every push.

4Your app uses clean (path-based) URLs via usePathUrlStrategy(), not #/ hash routing. This project already includes web/404.html, which redirects any deep link (e.g. a hard refresh on /generator) back to index.html so GitHub Pages' static hosting doesn't 404. No extra setup needed — it's already in the repo.

3. How to Use the App

Splash & Loading

On first load, a neon house draws itself over 3 seconds, then a glowing progress bar fills from 1% → 100% before landing on the Dashboard.

Dashboard

  • Toggle between 2D Generator and 3D Viewer mode using the pill switch.
  • Two glassmorphism cards count up to show your total Plans Generated and 3D Views Rendered — these numbers persist locally via Hive.
  • Tap Open 2D Generator / Open 3D Viewer to launch the selected mode. Tap Theme Lab (bottom right) to change the color scheme.

2D Generator

  • Enter your plot's Length and Width in feet.
  • Tap Generate 5 Plans — five distinct randomized layouts appear, each drawn live with CustomPainter (rooms, walls, dimensions).
  • Each card has its own Refresh icon (🔄) to re-roll just that one layout, and a Download icon (⬇) to export it as a PNG image.

3D Viewer

  • Pick which of your 5 generated plans to view from the dropdown at the top right.
  • Orbit: click-and-drag anywhere on the 3D canvas to rotate the view.
  • Zoom: pinch (trackpad/touch) or use the +/− buttons in the control bar.
  • Day / Night toggle: switches ambient lighting and adds a soft glow to each room, simulating interior lights at night.
  • Reset Orbit snaps the camera back to the default angle.

Theme Lab

Choose from 10 neon color schemes. Tapping a tile applies it instantly app-wide with a soft flash transition, and your choice is remembered on your next visit (saved in Hive).

Tech Notes

  • State management: Riverpod (StateNotifierProvider for plan + theme state, FutureProvider for dashboard stats).
  • Routing: GoRouter with clean URLs (see Section 2 for the 404.html trick).
  • Storage: Hive (via hive_flutter), which runs on IndexedDB in the browser — fully offline, no server.
  • 2D rendering: Custom CustomPainter — no image assets, no canvas library dependency.
  • 3D rendering: A hand-built isometric matrix-projection CustomPainter (yaw/pitch/zoom), chosen over a Three.js/WebView bridge to avoid CDN dependencies and keep the app 100% offline-safe on static hosting.
